# 七、评测实验室：从手算到可复现消融

> 源码：[evaluation 包](../src/main/java/com/xb/rag/evaluation/)。本章评估的是 **chunk 排名**，不是生成答案，也不报告幻觉率。

## 先跑最小实验

在仓库根目录执行，要求 Java 21、Maven 3.9+，无需启动外部服务：

```bash
mvn -Dtest=RrfFusionTest,EvalRunnerTest,RetrievalAblationTest test
```

- `RrfFusionTest`：验证跨路求和、1-based 名次、重复项处理、稳定排序及输入不变等融合语义。
- `EvalRunnerTest`：验证指标计算、边界输入及逐查询报告。
- `RetrievalAblationTest`：对照冻结的 Vector-only、BM25-only 与 RRF 排名，输出 `target/evaluation/ablation.json`。

**实验性质：冻结的合成排名 fixture。** “Vector / BM25”表示事先写定的候选列表，不调用 embedding、Elasticsearch 或向量索引。它用于复现融合与指标行为，既不是模型/索引的真实基准，也不证明 RRF 总是更好。每次运行检查报告是否为本次生成；`target/` 中的旧文件不是成功证据。

仓库没有 `mvnw`。首次运行可能需要下载依赖；上述定向测试不等于全量 `mvn test`，应用上下文测试另有外部服务要求。

## 两种执行路径，分开解释结论

| 路径 | 候选来源 | 能证明什么 |
|---|---|---|
| 离线排名实验 | 冻结合成候选 + 人工相关 ID | 融合与指标实现是否符合约定；指定 fixture 上的差异 |
| 真实检索评估 | `EvalRunner` 注入 `HybridSearchService`，查询已有两路索引 | 在给定语料、模型、索引、配置和标签下的检索质量 |

真实路径不能用“固定返回空结果”的占位检索器代替。报告必须保留每个问题实际返回的排名，才能区分检索无命中、标签不匹配与计算错误。两条路径都不调用回答生成来计算指标；样本的 `expectedAnswer` 字段不参与本次排名评分。

## 指标口径：先定义，再比较

对问题 q，令 `Gq` 为去重后的相关 chunk ID 集合，`Lq` 为返回的有序结果。只观察前 K 个位置；同一个相关 ID 不能重复贡献命中或增益，重复项不能刷分。以下手算使用无重复结果。

```text
hits(q,K)    = 前 K 位中命中的不同相关 chunk 数
Recall@K     = hits(q,K) / |Gq|
Precision@K  = hits(q,K) / K
RR@K         = 1 / 首个相关结果的名次；前 K 位无命中则为 0
DCG@K        = Σ rel(i) / log2(i+1)，i 从 1 到 K，二值 rel(i) ∈ {0,1}
IDCG@K       = Σ 1 / log2(i+1)，i 从 1 到 min(K, |Gq|)
nDCG@K       = DCG@K / IDCG@K
```

全局 Recall、Precision、MRR 与 nDCG 均为**逐查询等权宏平均**；其中 MRR 是各查询 RR 的平均，不是“平均排名的倒数”。

- Precision 的分母固定为 **K**，不是实际返回条数。返回不足 K 条时，未填满的位置按未命中处理。
- Recall 的分母是该查询所有标注相关 chunk 的数量，不是 K，也不是样本数。
- 二值 nDCG 不使用分级相关性分数；需要 graded relevance 时必须另外定义标签与实现，不能只改报告名称。
- 重复相关 ID 不应提高指标；融合输出自身应按 `chunkId` 唯一。
- 不同实现可能对重复结果、未标注结果及 Precision 分母采用不同约定，对外对比前要核对，不能只比较同名指标。

### 手算：有命中但返回不足 K

**以下仅为公式教学示例，不是测试运行输出。** 设 K=3：

| 问题 | 标注相关 ID | 实际排名 | Recall@3 | Precision@3 | RR@3 | nDCG@3 |
|---|---|---|---:|---:|---:|---:|
| q1 | `{A, B}` | `[X, A]` | 1/2 | 1/3 | 1/2 | `(1/log2(3)) / (1+1/log2(3)) ≈ 0.386853` |
| q2 | `{C}` | `[]` | 0 | 0 | 0 | 0 |
| 宏平均 | — | — | 0.25 | 0.166667 | 0.25 | 0.193426 |

q1 返回两条，但 Precision 仍为 `1/3`，不是 `1/2`。q2 有已知相关证据，只是本次检索为空，应该计入 0 分。

### 空检索、未标注与无答案，不是一回事

| 情况 | 本评估器如何处理 | 原因 |
|---|---|---|
| 有相关标签，检索返回空列表 | 四项指标为 0，保留逐查询记录 | 是真实的召回失败 |
| 数据集为空 | 拒绝运行 | 不能生成有意义的宏平均 |
| 查询缺少相关标签 | 拒绝运行 | “未标注”不能假装成“没有相关文档” |
| K 非法（例如 0 或负数） | 拒绝运行 | 不存在有效的截断与分母 |
| 经人工确认语料中无答案 | 单独放入无答案/拒答评测集 | 本排名评估要求非空相关集合；不应制造假 ID 凑标签 |

## 读报告：别只看一行平均分

`EvalReport` 应保留汇总指标与逐查询 trace：问题、相关 ID、实际排名 ID、命中情况及单条指标。离线消融还应能对应到两路输入和融合后的排名；具体 JSON 字段以本次生成报告和源码为准，不把示意 JSON 当固定接口契约。

复盘每次改动时：

1. 核对 query 数、K、标签和候选来源；任何一项变了，都不是同一实验。
2. 先筛选 `ΔRecall < 0` 或 `ΔnDCG < 0` 的查询，再看平均提升。
3. 查相关片段是否在候选并集中：不在是召回问题；在但出不了最终 K，是排序/截断问题。
4. 定位标签错误、ID 漂移、重复内容、路由失效或真正的算法回归，记录结论及原始 trace。
5. 小样本报告同时展示逐条结果；业务样本充足时再对逐查询差值做配对 bootstrap 等不确定性分析，不对玩具 fixture 宣称统计显著。

## 构建业务查询集

### 1. 分层采样，不只挑容易的问题

| 查询层 | 示例（仅示意） | 主要诊断目标 |
|---|---|---|
| 精确实体 | “ERR_AUTH_401 对应哪条处理步骤？” | 术语、编号、分词与字段权重 |
| 语义改写 | “为什么登录后很快又被要求验证？” | 字面不同但证据相关的召回 |
| 多 chunk 联合证据 | “申请条件和审批例外分别是什么？” | 是否同时找齐多个必要片段 |
| 空召回回归 | 已知有答案，但某一路或融合返回空 | 过滤、索引遗漏、ID 错配与路由故障 |

另建真实无答案集，测试拒答而非混入非空标签排名集。分层占比应由使用场景决定，并在报告中同时给出各层样本数和指标；不能用实体型查询的提升掩盖联合证据退化。

多 chunk 问题的 Recall 只能衡量找回多少标签，不能证明“信息足以回答”。若存在多组可替代证据或必须同时命中的证据组，应额外记录证据组定义；当前二值 ID 指标不表达这种逻辑。

### 2. Pooling 标注与困难负例

- 合并多种检索配置的较深候选，按稳定 ID 去重，隐藏系统来源后人工判断与问题的相关性。
- 标注时查原始文档及上下文，不只看截断片段；区分“提到术语”与“提供答案证据”。
- 加入相邻版本、相同标题、相似编号等困难负例；重要样本由第二人复核，保留分歧裁决。
- Pooling 不是穷尽语料。新系统命中未标注片段时先补判，不能武断认为它不相关；记录标签覆盖范围和版本。
- 查询来自日志时先脱敏、去重，避免把敏感数据放进测试 fixture。

### 3. 防泄漏划分

开发/训练集用于形成策略，验证集用于选候选 K、RRF 参数或重排阈值，测试集只用于冻结方案的最终比较。按文档家族、主题、近重复查询或时间切分，而不只是随机逐行切分；同一手册的轻微改写不应同时落入调参与测试集合。

不要看完测试集退化再不断调参，却继续把它称为独立测试集。需要调整时回到开发/验证流程，并重新保留未见测试数据。

## 可复现实验协议

### 冻结对象

每次业务实验保存一份与报告关联的清单（这是实验要求，不是当前自动产物）：

- 语料清单、文件内容哈希、文档版本、解析器与清洗规则版本。
- chunk 快照：`chunkId → docId / 内容 / 位置 / 版本`；重分块会改变标签对象，必须重映射或重标注。
- embedding 模型标识、版本、维度与预处理；索引快照、距离度量、分析器、字段映射及 ANN 参数。
- 查询集、相关性标签与划分版本；候选 Nv/Nb、融合输出 Kf、评测 K。
- 应用修订、运行环境、路由错误及耗时记录。冻结合成排名时保存输入列表本身，而非声称冻结了真实模型。

### 一次只改变一个因素

| 对照 | 保持不变 | 可解释的结论 |
|---|---|---|
| Vector-only / BM25-only / RRF | 同一组候选快照、标签、评测 K | 在这组排名上，融合是否改善排序 |
| 候选深度实验 | 语料、模型、索引、标签、最终 K | 增大候选预算的收益与代价 |
| 分块实验 | 原始语料、查询集和证据定义 | 需为各分块版本重新映射标签，不能沿用失效 ID |
| Rerank 实验（待集成） | 同一融合候选、外部模型版本、最终 K | 重排收益；另测调用成本及失败降级 |

先计算候选并集的相关证据覆盖率，再计算最终 K 排名质量；前者是后者的上限。延迟需在真实服务上独立测量，分离冷启动、缓存和并发条件；合成排名测试耗时不能作为检索服务 p95。

## 检索评测与答案评测分层

检索指标回答“证据找对了吗、排前了吗”。答案评测还需固定生成模型、Prompt、上下文、引用及标准答案，逐条核验事实支持、完整性、引用蕴含和无答案时的拒答。

`expectedAnswer` 目前仅保留为样本字段；`EvalRunner` 不据此生成或裁判回答。`hasHallucination` 也不是本实验指标。模型自评不是人工真值，没有答案评测不能报告“幻觉率下降”或设定任意上线目标。

## 生产接入的下一步与验收条件

以下是**尚待完成的验收工作**，不是已实现能力清单：

| 工作 | 可检查的验收条件 |
|---|---|
| 双索引导入与更新 | 相同版本和 ID 可在两路查到；失败重试不重复；更新/删除后旧版本不再可见；报告可追溯到索引快照 |
| 租户与权限过滤 | 权限来自认证上下文，在两路检索前一致执行；跨租户负例为零泄漏；失去任一路过滤时拒绝请求而非开放查询 |
| Rerank 接入 | 合同测试覆盖真实服务响应、超时、部分失败；保留原始排序用于降级；对同一候选集完成分层评测 |
| 回答质量 | 独立答案标签与人工复核；空证据、冲突证据、无效引用均有测试；不要用检索分数代替事实支持 |
| 回归与运行可靠性 | 阈值由验证集和业务约束预先确定；测试集回归逐条审查；真实依赖下记录延迟、错误率和降级行为 |
