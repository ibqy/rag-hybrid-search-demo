# 三、多路混合检索（Hybrid Search）

## 问题背景

单一向量检索对专有名词、编号（订单号 `ORD-2024-001`、设备编码）召回很差；BM25 对语义相似但字面不同的问题（"笔记本电脑" vs "笔记本"）不行。混合检索 = 两路互补。

## 两路召回设计

> 源文件：[retrieval 包](../src/main/java/com/xb/rag/retrieval/)

### 1. 向量语义检索

[`VectorRetriever.java`](../src/main/java/com/xb/rag/retrieval/VectorRetriever.java)
- 封装 Spring AI `VectorStore`，查询时自动 embedding
- 支持 `similarityThreshold` 元数据过滤（租户隔离）

```java
public List<SearchResult> search(String query, int topK) {
    List<Document> docs = vectorStore.similaritySearch(
        SearchRequest.query(query).withTopK(topK));
    return docs.stream().map(this::convert).toList();
}
```

### 2. BM25 关键词检索

[`Bm25Retriever.java`](../src/main/java/com/xb/rag/retrieval/Bm25Retriever.java)
- Elasticsearch `multi_match` 查询
- 同时对 content 和 sectionTitle 做关键词匹配
- 专有名词匹配远超向量检索

```java
SearchResponse response = esClient.search(s -> s
    .index(index).query(q -> q
        .multiMatch(m -> m
            .query(query)
            .fields(List.of("content^3", "sectionTitle^5")))), SearchResult.class);
```

## 结果融合：RRF 算法

[`RrfFusion.java`](../src/main/java/com/xb/rag/retrieval/RrfFusion.java)

RRF（Reciprocal Rank Fusion）融合两个 rank 列表：
```
score = 1 / (60 + rank_vector) + 1 / (60 + rank_bm25)
```
- 同一个 chunk 在两个列表中都出现 → 得分叠加，排名飙升
- 只在单一列表出现 → 保留，但排名靠后
- 常数 k=60 平滑极端排名

```java
Map<String, MutableDouble> fused = new LinkedHashMap<>();
for (int rank = 0; rank < results.size(); rank++) {
    String key = r.getChunkId();
    fused.merge(key, new MutableDouble(1.0 / (K + rank)), MutableDouble::add);
}
```

## 混合检索编排

[`HybridSearchService.java`](../src/main/java/com/xb/rag/retrieval/HybridSearchService.java)
```java
List<SearchResult> vectorResults = vectorRetriever.search(query, vectorTopK);
List<SearchResult> bm25Results = bm25Retriever.search(query, bm25TopK);
return rrfFusion.fuse(vectorResults, bm25Results, finalTopK);
```

## 调参建议

| 参数 | 默认值 | 调整方向 |
|------|--------|---------|
| vectorTopK | 20 | 语义丰富的场景增大 |
| bm25TopK | 20 | 专有名词多的场景增大 |
| finalTopK | 8 | 根据 LLM 上下文窗口调整 |
| RRF k | 60 | 越大多路结果越均衡 |

## 面试要点

- 单纯向量检索为什么识别不了 `ORD-2024-001`？embedding 把 ID 编码成稠密向量，精确字符信息丢失
- RRF 为什么比简单合并好？考虑了排名权重，防止单一列表主导
- 为什么叫"混合检索"？不是代替，是互补：向量找语义，BM25 找精确匹配
