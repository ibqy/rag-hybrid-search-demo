# 二、高级分块策略（抛弃固定切分）

## 问题背景

固定 512 字符切分，一句话/表格被拆两半，语义被割裂。不同文档类型需要不同策略。

## 核心设计

> 源文件：[chunking 包](../src/main/java/com/xb/rag/chunking/)

所有分块策略实现 `ChunkStrategy` 接口：
```java
public interface ChunkStrategy {
    List<Chunk> chunk(List<DocSegment> segments, ChunkConfig config);
}
```

### 1. 层级切片（推荐技术文档）

[`HierarchicalChunker.java`](../src/main/java/com/xb/rag/chunking/HierarchicalChunker.java)
- 按 docId + sectionTitle 分组
- 同一章节的段落保持在一起
- 章节超长才内部切分，标题边界不被破坏

```java
// 按 (docId, sectionTitle) 分组
Map<String, List<DocSegment>> groups = segments.stream()
    .collect(Collectors.groupingBy(s -> s.getDocId() + "|" + s.getSectionTitle()));
```

### 2. 语义切片（适合自由文本）

[`SemanticChunker.java`](../src/main/java/com/xb/rag/chunking/SemanticChunker.java)
- 相邻句子组计算向量余弦相似度
- 相似度低于阈值说明语义变化，在此切分
- EmbeddingModel 不可用时降级到 FixedSize

```java
double similarity = cosineSimilarity(
    embeddingModel.embed(curGroup), 
    embeddingModel.embed(nextGroup)
);
if (similarity < threshold) { /* 切分 */ }
```

### 3. 自适应重叠窗口

[`AdaptiveOverlapChunker.java`](../src/main/java/com/xb/rag/chunking/AdaptiveOverlapChunker.java)
- 装饰器模式，包装任意 ChunkStrategy
- 短块(<100字符)重叠为 0
- 长块(>1000字符)最大重叠
- 表格/代码块重叠为 0，防止重复

### 4. 特殊内容保护

- 表格：整表作为单独 chunk，转 Markdown 格式
- 代码块：完整保留，不在代码中间截断
- 太短(<20字符)的 chunk 直接过滤

### 5. 编排器

[`ChunkingOrchestrator.java`](../src/main/java/com/xb/rag/chunking/ChunkingOrchestrator.java)
- 根据 contentType 路由策略
- 校验 chunk 合法性（空内容、过长二次拆分）

## 四种策略对比

| 策略 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| 固定大小 | 简单快 | 语义割裂 | 兜底降级 |
| 层级切片 | 语义完整 | 依赖标题质量 | 技术文档、手册 |
| 语义切片 | 自然边界 | 算力高 | 自由文本、新闻 |
| 自适应重叠 | 兼顾上下文 | 复杂 | 搭配任意策略 |

## 面试要点

- 固定切分的问题：一句话拆两半 → embedding 向量偏差 → 检索不准
- 语义切片为什么比固定好？在语义边界切分，chunk 内部语义完整
