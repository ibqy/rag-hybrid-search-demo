# 二、高级分块策略：边界、预算与标签版本

## 不要预设“语义分块一定更好”

块太小可能拆散证据，块太大会混入噪声并占据上下文预算。策略是否有效，取决于文档结构、查询类型与 embedding 模型，必须在固定数据上比较。

> 源码：[chunking 包](../src/main/java/com/xb/rag/chunking/)。各策略实现 `ChunkStrategy`，由 `ChunkingOrchestrator` 按配置名称选择，不是自动理解所有内容后智能路由。

## 策略实现与适用条件

| 策略 | 实现与用途 | 当前边界 |
|---|---|---|
| [固定大小](../src/main/java/com/xb/rag/chunking/FixedSizeChunker.java) | 易于复现的基础策略与兜底 | 字符预算不等于模型 token 预算；需检查证据边界 |
| [层级分块](../src/main/java/com/xb/rag/chunking/HierarchicalChunker.java) | 按文档和章节标题分组，超长章节继续按段落组块 | 依赖标题质量；同名章节可能被归到同组，单个超长段落仍需检查 |
| [语义分块](../src/main/java/com/xb/rag/chunking/SemanticChunker.java) | 对段落组做 embedding，依据相邻组余弦相似度决定边界 | 有额外模型调用；无模型时回退固定分块，不代表所有调用异常都回退 |
| [自适应重叠](../src/main/java/com/xb/rag/chunking/AdaptiveOverlapChunker.java) | 包装基础策略，根据长度/类型计算 overlap | 当前只写入/调整 overlap 元数据，没有据此实际拼接或裁剪正文 |

### 语义分块的降级要读到分支

`SemanticChunker` 没有可用模型对象时使用固定分块；单个 embedding 调用失败时则放入空向量，无法计算的相似度按“不切分”处理。因此不能宣称“模型异常总会安全回退”；应在真实服务测试中检查异常导致的超长合并与证据边界。

### 特殊内容保护不是绝对保证

层级分块的超长章节拆分分支会单独处理表格/代码，但短章节可以整体组块；语义策略也可能继续合并内容组。不要笼统承诺每个表格永远独占一个 chunk 或任何代码都不会被破坏。特别大的表格还需要明确的行/列语义拆分策略，当前没有完整实现。

## 配置口径

以 [ChunkConfig](../src/main/java/com/xb/rag/chunking/ChunkConfig.java) 为准：

| 字段 | 类中初始值 | 含义 |
|---|---|---|
| `chunkSize` | 512 | 目标字符数；并非所有策略的绝对硬上限 |
| `chunkOverlap` | 128 | 重叠配置；是否影响正文取决于具体策略 |
| `minChunkSize` | 50 | 编排器过滤短块的字符下限 |
| `strategy` | 需设置 | 选择已注册的策略名称 |

`ChunkingOrchestrator` 检查空内容与最小长度，不承担通用的超长二次切分。应用实际值还要核对 Bean 配置，不能只看类默认值。

## 实践：只改一个分块因素

1. 固定语料和解析结果，选取实体定位、语义改写、跨段落联合证据三类问题。
2. 先运行固定大小基线，记录 chunk 数量、长度分布、证据断裂和重复比例。
3. 保持 embedding、索引、查询和候选预算一致，再比较层级或语义方案。
4. 在分块后重新映射相关证据标签，再比较 [Recall / nDCG](./07-RAG评估体系.md)。不能让旧 ID 指向新 chunk 后直接比指标。
5. 如果尚未完成真实入库，先检查 chunk 内容与标签映射；冻结排名消融本身不衡量分块效果。

### 为什么重分块需要重标注或映射

**示意**：原文“申请条件”与“例外审批”属于同一问题的两份证据。版本 v1 把它们放入 A，v2 分成 B、C。若仍用 `{A}` 评估 v2，零命中只说明标签过期；若只标 B，则漏掉联合证据要求。

保存“问题 → 原始证据位置 → 当前 chunk ID”的映射，可以区分真实退化与 ID 变化。当前 chunk 使用随机 ID 的位置不能当作跨运行稳定快照，应冻结生成结果再评测。

## 验收与排查

- 短而重要的错误码是否被最小长度过滤掉？
- 相同标题是否跨章节合并，正文顺序是否保持？
- 超长段落与表格是否超过 embedding 或生成模型输入上限？
- 声称有重叠时，正文真的重叠，还是只写了 metadata？
- 重复片段是否挤占最终 K，使同一证据被看作多次命中？
