# 五、幻觉抑制 + 溯源引用

## 问题背景

RAG 最大的痛点是 LLM 不遵守"仅用参考资料回答"的约束，编造不存在的事实。幻觉根源：LLM 预训练知识 + Prompt 约束不足 + 检索片段不相关。

## 三环抑制方案

> 源文件：[hallucination 包](../src/main/java/com/xb/rag/hallucination/)

### 第一环：强约束 System Prompt

[`PromptConstants.java`](../src/main/java/com/xb/rag/hallucination/PromptConstants.java)

```java
public static final String SYSTEM_PROMPT = """
    你是一个知识库问答助手。
    
    约束规则：
    1. 仅使用下面提供的参考资料回答问题
    2. 回答时标注引用来源 [1][2]...
    3. 参考资料不存在该信息时，回复："抱歉，参考资料中未找到相关信息"
    4. 严禁使用参考资料以外的知识
    5. 严禁编造数据、引用或事实
    
    参考资料：
    {context}
    
    用户问题：{question}
    """;
```

### 第二环：引用验证

[`CitationValidator.java`](../src/main/java/com/xb/rag/hallucination/CitationValidator.java)

LLM 回答后，验证其中的 `[1]` `[2]` 引用是否在检索结果范围内：
- 提取回答中所有 `\[\d+\]` 引用编号
- 检查编号是否超出提供的引用范围
- 过滤无效引用（如 `[99]` 而只提供了 8 条）

### 第三环：LLM 自校验

[`HallucinationDetector.java`](../src/main/java/com/xb/rag/hallucination/HallucinationDetector.java)

二次 LLM 调用，让模型自己验证回答是否忠于参考资料：

```java
public HallucinationCheckResult check(String question, String context, String answer) {
    PromptTemplate template = new PromptTemplate(VERIFICATION_PROMPT);
    ChatResponse response = chatModel.call(template.create(...));
    return parseVerificationResult(llmOutput);
}
```

验证 Prompt：
```
请判断以下回答是否完全基于参考资料，没有编造。
参考资料：{context}
回答：{answer}
输出格式：
幻觉判定：是/否
幻觉部分：具体编造内容/无
置信度：0.0~1.0
```

### 拒绝策略

多路召回融合后，如果所有片段得分都低于阈值，直接拒绝回答：
```java
if (results == null || results.isEmpty()) {
    return "抱歉，资料库中未找到相关信息";
}
```

## 工作流程

```
用户问题 → 混合检索 → 分数低于阈值？→ 直接拒绝
        ↓ 正常
    Rerank精排 + 过滤
        ↓
    引用组装 [1][2][3]...
        ↓
    System Prompt + 参考资料 → LLM 回答
        ↓
    引用验证 → 校验失败则修正
        ↓
    LLM 自校验 → 发现幻觉 → 标记预警
        ↓
    返回带引用标记的回答
```

## 面试要点

- RAG 幻觉来源：① LLM 使用自有知识覆盖检索结果 ② 检索片段不相关但 LLM 强行回答 ③ 引用标记被忽略
- 为什么不用一个很强的 System Prompt 就够了？LLM 对 System Prompt 的遵守程度不稳定，需要多环节校验
- 自校验会不会增加成本？会，但对高准确性场景值得；可在敏感查询（金融、医疗）才启用
