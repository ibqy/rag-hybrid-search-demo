# 六、向量库运维与增量更新：从骨架到验收

## 当前实现边界

> 源码：[vectorstore 包](../src/main/java/com/xb/rag/vectorstore/)。本章的持久化流程是待集成设计，不是已完成的存储服务。

| 组件 | 当前范围 | 尚未完成 |
|---|---|---|
| `VectorStoreConfig` | 选型与索引参数表达 | 不等于可用的 Spring AI `VectorStore` Bean 或完整自动建库 |
| `DocChangeWatcher` | 内容指纹计算与比较 | 持久化历史指纹、版本状态和并发更新控制 |
| `VectorStoreManager` | 初始化、分区、删除、重建等方法骨架 | 实际集合/索引/删除操作；当前主要记录日志 |
| `IncrementalUpdater` | 新增/更新流程骨架 | embedding 与可搜索双索引写入、失败恢复 |

`/api/docs/upload` 只解析分块并返回统计。`/api/docs/update` 返回 `updated` 也不能证明存储已更新。不要通过接口名、日志“完成”或配置字段推断真实写入已发生。

## 两路索引必须共享一份身份契约

混合检索以 `chunkId` 融合，要求相同 ID 在向量与文本索引中代表相同版本、相同内容。否则融合可能把两个版本的证据混在一起，评测也会把 ID 漂移误判成召回下降。

建议在实际接入前明确：

- 文档身份与版本：稳定 `docId`、来源、版本号/内容哈希。
- chunk 身份：与内容及分块版本关联的 ID、所属文档、位置；不得把一次随机生成的 ID 当作跨次导入稳定键。
- 可见性：tenant / ACL / deleted / activeVersion 如何在两路同步过滤。
- 运行状态：解析成功、向量完成、文本索引完成、可见版本已切换是不同阶段。

这些是设计要求；当前字段存在并不意味着上述契约已被执行。

## 指纹检测的正确用途

MD5 相同可以帮助跳过相同文件内容，但：

1. 历史指纹必须从可信持久化记录读取，而不是拿本次新指纹与自己比较。
2. 文件没变，解析器、分块策略或 embedding 模型变了，仍可能需要重建索引；版本键应包含处理管线版本。
3. MD5 是这里的变更线索，不是防篡改或安全校验保证；有完整性安全需求时应使用合适的加密哈希与身份校验。
4. “哈希未变”不能证明两路索引没有丢数据，还要有对账与修复能力。

## 待实现的一致性流程

```text
读取历史版本 → 计算内容/处理版本 → 解析并冻结 chunk 集
    → 写入新版本向量索引 + 文本索引
    → 校验数量、ID、内容与可查询性
    → 切换可见版本
    → 清理旧版本并对账
```

**先删后写并不天然保证一致性**：写入失败会造成可用证据缺口；两个存储也没有自动共享事务。版本化写入、显式状态机和可重试任务是可选设计，具体切换方式取决于存储能力。

验收时至少覆盖：

| 故障注入 | 期待观察到的行为（待实现） |
|---|---|
| 向量写入成功、文本写入失败 | 不宣告新版本完全可见；可以重试失败侧并最终对账 |
| 同一任务重复执行 | 相同版本不产生额外 chunk，状态可重复读取 |
| 两个版本乱序到达 | 旧版本不得覆盖较新版本 |
| 切换后清理失败 | 检索仍仅见 active 版本；清理可重试 |
| 删除后立刻查询 | 两路均不再返回已删除证据，而不只是日志显示“已删除” |

Kafka 相关类可作为异步处理入口的学习材料，但不能由此声称已有可靠的“上传 → 消息 → 双索引”闭环。异步系统还需验证生产者、消息契约、重试、幂等和失败状态。

## 索引选择：用真实基准替代参数口诀

pgvector 与 Milvus 是不同的存储选型。HNSW、IVF 及量化索引的可用名称和参数应以具体产品版本为准，不能直接互换配置。

| 方向 | 需要测量的取舍 |
|---|---|
| HNSW 图连接与搜索宽度 | 召回、内存、构建成本和查询延迟 |
| IVF 分区与探测数量 | 训练/构建要求、扫描范围及召回损失 |
| 量化 | 内存节省、精度损失及数据分布敏感性 |

固定模型、距离度量、维度和数据快照，用精确搜索或可靠基线对照 ANN 的 Recall，再测真实并发下的延迟。不要从 [冻结排名实验](./07-RAG评估体系.md) 的运行耗时推导索引性能。

## 权限与删除是检索前约束

当前 `RagController` 不使用 `tenantId`，两路没有完整的租户隔离。生产接入必须将认证得到的权限条件在两路候选阶段一致应用，并确认软删除过滤也真实生效。仅在返回答案时隐藏引用，无法防止未授权内容进入模型上下文。

最终验收应包括：跨租户负例、角色撤销、软删除、版本切换、过滤失效和缓存污染。未通过前，不应把本项目作为多租户知识库使用。
